# Native CPU and event-cost qualification, 2026-11-09

This comparison separates two questions: the total cost of 0.12.7
(`3f4f064`) versus the complete 0.13.0 candidate, and the cost of one exact
CPU transformation after the acoustic work was frozen. It measures the
public Performer on Linux x86-64 with GCC 14.2, Release `-O3 -DNDEBUG`.
It is not a Reason SDK, ARM, battery, or universal deadline measurement.

## Workload and measurement

All three executables use the same `Tools/MeasureCpu.cpp`. The two acoustic
versions and the pre-optimization snapshot were built with the same DSP
flags. Setup, instrument design, reset, file parsing, allocation, warm-up,
analysis and export are outside the timed interval. Each measured callback
includes scheduled MIDI/control dispatch, rendering 64 host frames at
48 kHz, and the same small timer overhead. Calling-thread CPU and elapsed
wall time are recorded together, retaining every callback in CSV.

The coordinator reserves an otherwise idle compute window. There are three
alternating paired rounds (A/B, B/A, A/B) for each comparison:

- Three material presets at 1x/2x/4x: all native strings held with periodic
  re-plucks; bend/palm gestures; and a fast four-string re-pluck pattern
  (46.875 attacks/s, 11.72/s per string). Each case renders two timed seconds.
- All nine actual frozen Rack factory `.repatch` files at shipping 1x,
  using their mapped controls and a two-second single/chord/velocity score.
  These are distinct from the three material stress presets. The short
  factory score mostly visits fresh strings, so it does not strongly
  exercise the recontact optimization.
- Separate 0.1-second supplements: all 27 steel/nylon or 16 gut strings
  attacked together from silence, and all strings reattacked together after
  the held-string warm-up. There is exactly one such event in callback zero
  per material/factor/round. Its CPU/wall duration is reported separately
  from the other 74 callbacks. These use prepared, warm allocated memory;
  they are not cold-cache or process-start measurements.

The shared evidence directory retains the binary/harness/resource hashes,
execution order, raw JSON and paired callback CSV. Matrix validation checks
unique identities, all requested presets/factors/patches, equal frame
counts and finite positive timings. The output directory is never silently
reused.

## Profile and exact transformation

A discovery Callgrind run over the warmed, dense steel re-pluck workload
at 1x collected 93,221,857 instructions. `process` accounted for 92.59%
inclusive and `noteOn` for 6.29%; the modal bank accounted for 25.38%.
Collection excludes setup/warm-up but includes the callback-loop audio copy
and common bookkeeping, unlike the narrower native callback clock interval.
These are collected workload instructions, not pure `process` self time.

The retained candidate replaces two integer remainders at each of four
Catmull contact taps with one bounded wrap. After periodic reduction, the
base index lies in `[0,count-1]`, and its neighbours lie in `[-1,count+1]`
with `count >= 2`, so one correction is sufficient. The rare rounded
`i == count` endpoint is normalized only after computing the original
fraction. Floating arithmetic and accumulation order are unchanged.
Disassembly removes 16 integer-division instruction sites from `noteOn`.
The change adds no approximation, table, filter reduction or quality switch.

An independent scalar oracle covers 89,604 edge cases including counts two
and three, every base index, maximum capacity, and `nextafter` positions
around positive/negative period multiples. Outputs are bit identical.
Public-Performer parity before the final event supplements covers 54 cases
(three materials, 1x/2x/4x, dense/gestures/re-pluck/idle/factory plus all nine
actual factory patches), 2,592,000 interleaved float samples, also byte exact.

The larger delay buffers are a required range-safety correction: A0 bent
down an octave at 192 kHz exceeded the old capacity. This increases the
amount copied/cleared during contact, which is why event-block cost is
measured separately. Shortening those operations without tracking valid
history would be unsafe during subsequent bends.

A final matched Callgrind pair uses the same current harness against frozen
preopt and optimized DSP, steel at 1x, 75 measured callbacks. Re-pluck workload
instructions fall from 93,222,203 to 93,095,059 (-0.136%); the one all-string
reattack workload falls from 128,100,587 to 127,086,070 (-0.792%). In that
reattack case, inclusive `noteOn` instructions fall from 40,068,216 to
39,053,699 (-2.532%). Instruction counts weight an integer division like
any other instruction, so removing its latency can save substantially more
native CPU time than the instruction-count percentage suggests. These
counter comparisons support the targeted change; no Valgrind wall/CPU time
is used as a performance result.

## Measured results

The exclusive native window ran from approximately 09:38 to 09:45 UTC.
All 72 timed invocations / 648 case records passed the output and matrix
checks. The additional 18 cold/reattack parity cases add 172,800 float samples;
all 72 parity cases / 2,764,800 floats are byte identical.

The table shows the median, across the requested cases, of each case's
three paired relative changes in mean calling-thread CPU. A negative value
is cheaper. Cold/reattack rows instead use the event callback's CPU time.
The case range is variation across presets/factors, not a confidence interval.

| Workload | Original 0.12.7 → final | CPU-only change | CPU-only case range |
| --- | ---: | ---: | ---: |
| Dense held strings | -2.99% | +2.39% | -0.52% to +7.03% |
| Bend/palm gestures | +0.87% | +0.36% | -7.57% to +3.12% |
| Rapid re-plucks | -7.64% | -3.37% | -6.90% to -0.70% |
| Nine factory patches | -2.30% | -0.59% | -9.67% to +2.18% |
| First all-string attack | +2.98% | +2.23% | -10.67% to +9.97% |
| All-string reattack | -30.36% | -31.51% | -35.25% to -27.07% |

The pre/post `AculyreEngine::process` object-code regions have identical
32,900 bytes at the same offset (SHA-256
`c32b0d94f04949cf56957ee9bc858c2a71984c1cdc290611d0ab32a3a765850d`).
The optimized CMake executable is also byte-identical to a manual rebuild
using the baseline/preopt driver's exact command. These receipts rule out
a changed sample-loop instruction sequence or a driver-build mismatch; they
do not identify the cause of an observed timing change.

The CPU-only dense result is a regression in this experiment: eight of nine
case medians are slower, and the sum of their median CPU percentages rises
1.51%. It is not hidden as an overall win. The exact change is retained for
its consistent reduction of recontact event cost and rapid re-pluck cost.
Cold attacks do not enter the optimized recontact code; their mixed timings
also show the limits of short measurements on this cloud machine. Neither
small factory changes nor the dense regression establish a universal target
CPU result. There is no claim that every playing pattern becomes faster.

For the original→final comparison at shipping 1x, the means of the three
material-case median CPU percentages are 7.53%→7.16% for dense playing,
7.61%→7.48% with gestures, and 8.57%→7.90% for rapid re-plucks. The mean of
nine factory-patch medians is 8.66%→8.45%. These percentages are fractions
of one calling CPU thread, not Reason's device meter. The 2x gesture cases
increase (15.74%→16.54% by the same calculation), so even the aggregate
realism/correctness pass is not described as a uniform reduction.

## Event latency and limits

A first simultaneous attack at 1x averages 207→227 microseconds across the
three material medians in the original→final comparison. The larger safe
buffers and continuous release integration are setup/event costs, not a
free change in every path. The more expensive all-string recontact improves
from 3.929→2.863 ms at 1x, 7.452→5.145 ms at 2x, and 14.943→10.180 ms at 4x
(the mean of material medians). All three material presets' 1x recontacts
still exceed the 1.333 ms duration of a 64-frame callback. This is a retained
worst-event limitation, not a real-time deadline pass.

Across both paired comparisons, observed final **event callback** maxima are:

| Factor | First attack CPU / wall | All-string reattack CPU / wall |
| --- | ---: | ---: |
| 1x | 0.393 / 0.396 ms | 3.857 / 3.861 ms |
| 2x | 0.628 / 0.632 ms | 7.114 / 7.120 ms |
| 4x | 1.019 / 1.026 ms | 12.982 / 12.989 ms |

These are callback-zero events, not maxima borrowed from their later tail
callbacks. Observed final all-string reattack CPU maxima reach 12.982 ms in the
original→final runs and 11.330 ms in the CPU-only runs. Ordinary workloads
also contain isolated millisecond CPU/wall outliers; both clocks are kept
in the CSV, and these are not retrospectively dismissed as scheduling.
Warm-up and three alternating pairs improve comparability but do not certify
worst-case behavior on another machine. An audio-thread event budget or
further exact contact-work reduction remains future work.

Raw records, execution/harness/binary/resource hashes and paired summaries
are retained outside the checkout under
`/workspace/scratch/aculyre-evidence/cpu/`. No speed claim uses contended
build, test, parity or Valgrind wall times.
